# 구슬 속도 측정기

경사면을 굴러 내려오는 구슬의 **속도와 가속도**를 슬로모 영상으로 재는 웹앱.
잰 값을 굴림 운동 이론과 견주어 "제대로 굴렀는가, 미끄러졌는가, 마찰로 에너지가 샜는가"까지 보여 준다.

설치가 필요 없고, **영상은 기기 밖으로 나가지 않는다** — 모든 계산이 브라우저 안에서 이뤄진다.

## 두 가지 방법

**① 카메라로 바로 재기** — 자가 필요 없다. 화면을 익힌 뒤 [측정 시작] → 굴리기 → 다 지나가면
알아서 끝난다([정지]로 직접 끝낼 수도 있다). 잡히는 자리가 화면에 ◈ 로 표시되므로,
시작 전에 구슬이 제대로 보이는지 눈으로 확인할 수 있다.
다만 브라우저가 열어 주는 프레임레이트가 최대 60fps(iOS 사파리)라 슬로모보다 정확도가 낮다.
밝은 곳에서 써야 한다.

**② 슬로모 영상 넣기 (권장)** — 기본 카메라 앱의 슬로모(240fps)로 찍어 넣으면
오차가 10배쯤 줄어든다.

## 쓰는 법 (슬로모)

1. 기본 카메라 앱의 **슬로모**로 촬영 (아이폰: 설정 → 카메라 → 슬로모 비디오 녹화 → 1080p/240fps)
   - 폰을 고정하고, 경사면 옆에서 진행 방향과 직각으로
   - **자를 구슬이 지나갈 자리에 같이** 놓아야 cm 환산이 된다
   - 배경과 구슬을 대비시키고, 밝은 곳에서
2. 웹페이지에서 영상을 고르고 촬영 fps 선택
3. 자 위로 A·B 점을 옮기고 실제 길이 입력
4. 결과: 속도·가속도·경사각·이론 대조·그래프·궤적

## 왜 슬로모여야 하나

경사 30cm 에서 굴린 구슬은 초속 2m 쯤 된다.
30fps 면 한 프레임 사이에 67mm(구슬 지름의 4배) 움직여 길게 번진 자국만 남는다.
240fps 면 8.3mm 씩만 움직여 구슬 모양이 그대로 보인다.

## 자 없이 재기

거리 환산은 보통 길이를 아는 물건(자·A4 종이 29.7cm·신용카드 8.6cm·500원 동전 2.65cm)을
같이 찍어서 한다. 하지만 **구슬 자신을 잣대로 쓸 수도 있다** — 구슬 지름은 어차피 입력받으므로,
화면에서 구슬이 몇 픽셀인지 재면 환산이 나온다.

문제는 구슬이 빨리 지나가면 길게 번진다는 것이다. 그래서 **진행 방향과 수직인 폭**을 쓴다 —
번짐은 진행 방향으로만 늘어나므로 수직 폭은 실제 지름을 유지한다. 덩어리의 2차 모멘트에서
짧은 쪽 표준편차 σ를 구하면, 균일한 원판은 지름 = 4σ 다(픽셀 격자가 보태는 분산 1/12 은 뺀다).

| 번짐 | 지름 추정 오차 |
|---|---|
| 없음 | 0.3 ~ 1.8% |
| 보통 (4px) | 3.5 ~ 6.1% |
| 심함 (12px) | 7 ~ 10.4% |

자를 쓰면 기준선이 수백 px 라 오차가 1% 미만이지만, 구슬은 10~20px 뿐이라 이만큼 커진다.

## 원리

**추적** — 카메라가 고정돼 있다는 전제로, 영상 곳곳에서 9장을 뽑아 픽셀별 중앙값을 내면
구슬이 지워진 깨끗한 배경이 나온다. 각 프레임에서 배경과 밝기가 다른 픽셀을 연결해 덩어리로
묶고, 넓이·동그람 정도로 구슬을 고른 뒤 밝기차 가중 중심을 구한다(부분픽셀 정밀도 0.03px).

**속도·가속도** — 검출점에 RANSAC 으로 직선을 맞춰 궤적을 찾고(경사면을 벗어난 구간이나
손이 잡힌 프레임이 여기서 걸러진다), 그 직선에 투영해 1차원 위치 s 로 바꾼다.
s(t) 에 2차 곡선을 맞추면 계수에서 가속도가 바로 나온다. 프레임마다 차분하는 것보다 잡음에 강하다.

**이론 대조** — `a = g·sinθ / (1 + k)`. 속이 찬 구슬은 k = 2/5 라 미끄러질 때보다 1.4배 느리다.
위치에너지의 29%가 앞으로 나아가는 대신 스스로 도는 데 쓰이기 때문이다.

**시간 보정** — 아이폰이 슬로모를 240fps 원본으로 주는지 8배 늘린 30fps 로 주는지에 따라
속도가 8배 달라진다. MP4/MOV 헤더를 직접 읽어 정확한 프레임레이트를 구해 보정한다(`mp4.js`).

## 검증

같은 알고리즘의 Swift 판(네이티브 iOS 앱)과 **동일 입력에서 소수점 셋째 자리까지 일치**한다
(`test/port-check.mjs`). 합성 240fps 영상(1920×1080, H.264)으로 전 과정을 시험한 결과:

| 항목 | 참값 | 측정 | 오차 |
|---|---|---|---|
| 가속도 | 2.960 m/s² | 2.97 | 0.34% |
| 경사각 | 25.00° | 25.01 | 0.01° |
| 최고 속도 | 1.838 m/s | 1.84 | 0.3% |

실제 오차는 시간이 아니라 **거리 환산**과 **카메라 각도**에서 온다. 240fps 의 시간 정밀도는 이미 충분하다.

## 구조

```
index.html  style.css   화면
app.js      흐름·UI·그래프
analysis.js 배경 모델 · 구슬 검출 · 궤적 적합 · 물리 (순수 계산, Node 에서도 돔)
video.js    프레임 추출 (<video> + requestVideoFrameCallback)
mp4.js      MP4/MOV 헤더 파서 — 정확한 프레임레이트
```

## 시험

```bash
node test/port-check.mjs
```
